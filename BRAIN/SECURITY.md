# ProofLoop AI — Security and Privacy

## Trust boundaries

1. Browser → API: session cookie, JSON bodies, multipart uploads.
2. API → outbound research/URL fetch: untrusted destinations.
3. API → disk: SQLite file containing user documents and evidence snapshots.

## Controls implemented

| Area | Control |
|---|---|
| Secrets | Server-side env only; `.env` gitignored; no key ever sent to the browser; `/health` reports capability booleans, not values |
| Sessions | HMAC-SHA256 JWT (stdlib), httpOnly, SameSite=Lax, `Secure` when `PROOFLOOP_ENV=production`, 30-day expiry, constant-time signature compare |
| Passwords | scrypt (n=2^14, r=8, p=1) with per-user salt; 8–128 char policy; generic login error (no account enumeration) |
| Authorization | Every verification/upload query filters by `user_id`; cross-user access returns 404, not 403 data leakage |
| Input validation | Pydantic models with length caps; text 200k chars, title 160; email regex; claim 1–2000 chars |
| Uploads | extension + MIME allow-list, 10 MB cap counted while streaming, PDF parsed in-memory, filename sanitised (no path use) |
| URL fetch (SSRF) | http/https only, hostname DNS resolution then IP classified; loopback/private/link-local/multicast/reserved/metadata blocked; redirects disabled; 12s timeout; 3 MB cap; HTML stripped to text |
| Rate limiting | In-memory sliding window per IP+route class (auth 10/min, writes 30/min, reads 120/min) |
| CORS | Explicit origin list from env; credentials enabled only for those origins |
| Headers | `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, CSP in production, HSTS in production |
| Logs | Request method/path/status/duration and error codes only; no document text, excerpts, emails, or tokens |
| AI | Only claim extraction may use an LLM; excerpts/URLs never generated by it; keys server-side |
| Retention | Evidence snapshots retained with the job; no third-party analytics; no tracking pixels |
| Dependencies | Minimal pinned set; `npm audit` / `pip list` reviewed at handoff |

## Known limitations (honest)

- No email verification, password reset, MFA, or OAuth; guest sessions are device-cookie scoped.
- No per-user data deletion endpoint/UI in v1 (documented; DB is local file).
- SQLite single-writer: not suited to horizontal scaling.
- Rate limiting is per-process memory, reset on restart; use a shared store behind a multi-worker deploy.
- Screenshot OCR is disabled without a vision key and says so; no silent fallback.
- Wikipedia is a tertiary source; the product labels this and does not present its content as ground truth.
- `PROOFLOOP_SECRET` must be replaced in production; startup warns if the default is used.

## Reporting a problem

Security issues should be reported privately to the maintainer before public disclosure. There is no
bug bounty. No user data is sent to third parties other than the retrieved public source URLs and,
optionally, claim text to Gemini when that adapter is explicitly configured.
